# 0625-当前开发阶段完整方案、总体目标与预期效果

## 一、当前项目状态

当前项目已经完成本地医学影像 AI 辅助标注 Demo 的 MVP 闭环：

```text
上传数据集
→ 创建标注任务
→ 初始化 Label Studio 项目
→ mock 模型生成 AI 预标注
→ Label Studio 人工标注 / 修正
→ 后端拉取 annotation
→ 导出 simple_json / label_studio_json / mask_png
→ zip 下载
```

当前已经具备以下能力：

1. 支持单图、多图、ZIP 上传；
2. 支持基于数据集创建 bbox、polygon、bbox_polygon 三类任务；
3. 支持自动创建 Label Studio 项目并导入图片；
4. 支持 mock detection / mock segmentation 生成预标注；
5. 支持将 prediction 写回 Label Studio；
6. 支持从 Label Studio 拉取人工保存后的 annotation；
7. 支持导出 simple_json、label_studio_json、mask_png；
8. 支持前端上传、任务详情、预标注触发、导出下载。

当前项目已经不是“能不能跑通”的阶段，而是进入了：

```text
本地 MVP 闭环
→ 可展示产品雏形
→ 更完整的 AI 辅助标注体验
```

------

## 二、当前主要问题

目前前端与 Label Studio 的关系仍然偏“跳转式集成”。

用户体验上存在几个明显割裂点：

```text
前端上传 / 创建任务
    ↓
点击“打开 Label Studio 工作台”
    ↓
跳转到独立 Label Studio 页面
    ↓
用户可能需要单独登录
    ↓
在 Label Studio 中查看 prediction 并人工确认
    ↓
回到前端刷新状态 / 导出
```

这会让用户感觉当前系统由两个工具拼接而成：

1. 你的前端负责上传、任务管理、预标注触发和导出；
2. Label Studio 负责真正的图片查看和标注编辑；
3. 两边状态需要用户主动切换和刷新。

下一阶段的核心目标是降低这种割裂感，让用户感觉自己是在一个统一的医学影像 AI 辅助标注平台中完成操作。

------

## 三、当前阶段总体目标

当前阶段总目标：

```text
在不破坏现有上传、预标注、导出闭环的基础上，
将系统从“前端 + Label Studio 跳转式集成”
升级为“前端内完成任务查看、AI 预标注、标注工作台、状态同步、导出下载”的一体化 Demo。
```

更具体地说，本阶段希望达成三个目标：

### 目标 1：提升前端与 Label Studio 的一体化体验

将原来的跳转式使用方式：

```text
前端页面 → 新窗口打开 Label Studio
```

优化为：

```text
前端任务详情页 → 内嵌 Label Studio 工作台
```

用户不需要离开当前前端页面，就可以进入当前任务对应的标注工作台。

------

### 目标 2：实现图像级标注入口和状态回流

用户不应只看到“打开工作台”这个笼统入口，而应该能从某一张图像直接进入对应 Label Studio task。

目标体验：

```text
图像状态表
    ↓
点击某张图像的“进入标注”
    ↓
当前页面内打开该图像对应的 Label Studio task
```

同时，用户在 Label Studio 中保存 annotation 后，前端可以通过“同步状态”或后续自动同步机制更新图像状态。

------

### 目标 3：逐步接入真实模型，替换 mock 模型

当前 mock 模型已经验证了预标注流程，下一步需要逐步接入 1-2 个真实模型：

```text
real_detection_v1
real_segmentation_v1
```

其中推荐路线为：

```text
检测模型生成 bbox
→ 分割模型基于 bbox prompt 生成 mask / polygon
→ 结果写入 Label Studio prediction
→ 人工确认或修正
→ 导出正式 annotation
```

但真实模型接入不应先于前端一体化体验。建议先把 Label Studio 嵌入、图像级入口、状态同步做顺，再接真实模型。这样模型一接入，演示效果会马上完整。

------

## 四、预期最终效果

完成本阶段后，系统应具备如下演示效果：

```text
1. 用户上传医学影像数据集；
2. 创建 bbox / polygon / bbox_polygon 标注任务；
3. 触发 AI 预标注；
4. 前端显示每张图像的 prediction 状态；
5. 用户可在前端任务详情页内打开 Label Studio 标注工作台；
6. 用户可从某张图像直接进入对应 task；
7. 用户在 Label Studio 中确认或修正 prediction；
8. 回到前端后同步 annotation 状态；
9. 前端显示哪些图已保存人工 annotation；
10. 用户选择导出格式并下载 zip；
11. 后续可将 mock 模型替换为真实检测 / 分割模型。
```

------

## 五、现阶段开发原则

本阶段不是推倒重来，也不是重写 Label Studio。

必须遵守以下原则：

1. 不破坏当前已验证的上传、预标注、导出流程；
2. 不重写 Label Studio 标注画布；
3. 不源码级 fork Label Studio；
4. 不做登录、权限、多人协作；
5. 不做 DICOM、3D、视频；
6. 不做训练调度；
7. 优先做本地单机 Demo 的一体化体验；
8. 保留 mock 模型作为 fallback；
9. 真实模型接入必须兼容现有 prediction 写入和导出流程；
10. 每个阶段必须可单独运行、验证、提交。

------

## 六、推荐阶段拆分

### 阶段一：Label Studio 前端内嵌与图像级入口

目标：

```text
解决“前端和 Label Studio 跳转割裂”的问题。
```

交付内容：

1. 任务详情页增加 Tab 或分区；
2. 增加“标注工作台”区域；
3. 使用 iframe 内嵌 Label Studio；
4. 图像列表中增加“进入标注”按钮；
5. 点击图像后在 iframe 中打开对应 Label Studio task；
6. 增加基础登录提示和刷新按钮。

这一阶段不做真实模型、不做 AI 预览、不做 LSF，不改 Label Studio 源码。

------

### 阶段二：状态同步、AI 预标注预览与导出面板增强

目标：

```text
让前端不仅能打开 Label Studio，还能清楚展示 prediction / annotation / export 状态。
```

交付内容：

1. 增加“同步 Label Studio 状态”按钮；
2. 后端拉取 predictions / annotations 并更新本地状态；
3. 前端图像表展示更完整状态；
4. 增加只读 AI 预标注预览；
5. 支持 bbox / polygon overlay；
6. 优化导出面板；
7. 展示导出记录和下载状态。

------

### 阶段三：真实模型接入与 Label Studio 配置增强

目标：

```text
将 mock AI 辅助流程升级为真实模型驱动的 AI 辅助标注流程。
```

交付内容：

1. 接入 real_detection_v1；
2. 接入 real_segmentation_v1；
3. 支持 bbox_polygon：先检测后分割；
4. 前端支持 mock / real 模型切换；
5. Label Studio labeling config 增加人工确认字段；
6. 导出中保留 AI 元数据；
7. 评估是否需要 Label Studio Frontend / LSF 深度集成。

源码级二开 Label Studio 暂不进入当前阶段。
